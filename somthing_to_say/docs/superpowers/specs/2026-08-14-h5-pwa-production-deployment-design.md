# H5/PWA 生产部署设计

日期：2026-08-14

## 目标

第一阶段将“有话说”部署为可通过手机浏览器、微信内置浏览器和二维码访问的响应式 H5 网页应用。后续根据真实使用情况，再评估是否增加微信小程序前端。

## 方案选择

### 第一阶段：H5/PWA

- 复用现有网页聊天前端，调整为移动端优先的响应式布局。
- 用户通过 HTTPS 链接或二维码进入，不要求安装独立客户端。
- 可以提供 PWA 添加到桌面的能力，但不承诺离线聊天；聊天、账号和会话数据仍需要联网。
- 管理员继续使用独立网页管理端。

### 暂不采用微信小程序作为首发形式

- 小程序需要重新实现 WXML、WXSS 和页面逻辑。
- 需要处理微信登录、合法请求域名、审核和版本发布流程。
- 当前浏览器 SSE 流式方案不能直接假设可在小程序中复用，后续可能需要 WebSocket 或非流式请求。
- 后端 API、账号、会话和安全逻辑仍应保持可复用，为未来小程序接入预留边界。

## 部署架构

```text
手机浏览器 / 微信内置浏览器
            |
            | HTTPS
            v
响应式 H5 页面 + 管理员网页
            |
            v
FastAPI 后端
      |             |
      v             v
PostgreSQL      持久化 RAG 存储
```

第一阶段可以由 FastAPI 同时提供 H5 静态页面和 API，减少部署组件。用户量增加后，再将静态资源独立放到 CDN，后端保持独立部署。

## 数据存储

### 开发和小范围试用

- 继续使用 SQLite。
- 数据库文件必须放在固定、可备份的数据目录。
- 不把数据库依赖放在临时目录或会被清理的容器文件系统中。

### 正式上线

- 使用 PostgreSQL 保存账号、令牌、会话、消息和软删除状态。
- 通过事务保证消息写入、用户删除会话和总管永久删除的一致性。
- 配置自动备份和恢复演练。
- 数据库只允许后端服务访问，不向浏览器暴露数据库连接。

RAG 文档和向量索引不能依赖 Serverless 实例的临时本地磁盘，应使用持久化卷或托管向量存储。具体提供方在部署阶段根据预算、地域和运维能力确定。

## 网络与域名

- 所有网页和 API 使用 HTTPS。
- 浏览器端只访问公开的 API 域名，不包含模型密钥或数据库凭据。
- 如果主要面向中国大陆用户，优先选择网络稳定的国内云服务器，并按平台和域名要求完成备案及 HTTPS 配置。
- 生产环境的模型密钥、数据库连接信息和管理配置只保存在后端部署环境中。

## 账号与会话

- 首发继续支持匿名方案和用户名密码方案。
- H5 端保存认证令牌，不保存密码。
- 会话仍由后端按用户身份隔离。
- 用户删除会话执行软删除；总管永久删除逻辑由后端权限控制，不由前端隐藏按钮承担授权。

## 回复传输

- 浏览器优先使用现有安全流式接口，显示动态等待状态并在首个增量到达后替换。
- 高风险或安全判断不确定的请求不发送未审核的流式草稿。
- 流式不可用时保留完整响应接口作为回退。
- 后续开发微信小程序时重新评估 SSE、WebSocket 或完整响应方案。

## 非目标

- 第一阶段不开发微信小程序前端。
- 不把 Vercel 作为当前 FastAPI、SQLite 和本地 RAG 的整体生产运行环境。
- 不在前端保存模型密钥、数据库凭据或密码。
- 不提供离线生成回复。
