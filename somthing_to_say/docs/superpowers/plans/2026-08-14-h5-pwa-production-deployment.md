# H5/PWA 生产部署 Implementation Plan

> 本计划只描述最终设计确认后的部署工作，当前阶段不执行代码和基础设施变更。

**Goal:** 将“有话说”以响应式 H5/PWA 形式发布，支持手机浏览器、微信内置浏览器和二维码访问，并为正式环境迁移到 PostgreSQL 和持久化 RAG 存储做好准备。

**Architecture:** 第一阶段由 FastAPI 提供 H5 静态页面和 API；开发阶段保留 SQLite，正式环境切换 PostgreSQL；RAG 文档和向量索引使用持久化存储。微信小程序作为后续独立前端，不作为首发依赖。

---

### Task 1: 固化 H5 移动端边界

**Files:**
- Modify: `static/index.html`
- Modify: `static/admin.html`
- Test: `tests/`

- [ ] 验证 390x844、768x1024 和桌面宽度下布局无溢出。
- [ ] 验证两个用户模式、动态等待状态、流式消息和错误回退可用。
- [ ] 验证管理员页面不进入普通用户聊天流程。
- [ ] 评估是否增加 PWA manifest 和添加到桌面能力；不承诺离线聊天。

### Task 2: 准备 PostgreSQL 生产存储

**Files:**
- Modify: `database.py`
- Modify: `config.py`
- Create: `scripts/migrate_to_postgres.*`
- Test: `tests/`

- [ ] 明确 SQLite 到 PostgreSQL 的字段、索引和软删除状态迁移映射。
- [ ] 保留用户名唯一性、角色权限、会话归属和消息顺序约束。
- [ ] 使用事务覆盖用户软删除和总管永久删除。
- [ ] 在测试数据库验证迁移、回滚和备份恢复流程。

### Task 3: 准备持久化 RAG 存储

**Files:**
- Modify: `rag.py`
- Modify: `config.py`
- Test: `tests/`

- [ ] 选择持久化卷或托管向量存储。
- [ ] 为知识库文档记录来源、更新时间和适用范围。
- [ ] 普通情绪倾诉默认不检索；学校流程和明确事实问题才检索。
- [ ] 检索无结果时如实说明，不编造联系方式和政策。

### Task 4: 配置 HTTPS 和生产服务

- [ ] 准备生产域名、HTTPS 证书和后端服务。
- [ ] 配置数据库、模型服务和部署凭据，仅放在后端环境。
- [ ] 配置自动备份和恢复演练。
- [ ] 验证 H5、API、流式响应、账号登录和管理员权限。

### Task 5: 评估微信小程序接入

- [ ] 根据 H5 实际用户量和使用反馈决定是否开发小程序。
- [ ] 复用后端身份、会话、消息和安全 API。
- [ ] 单独设计小程序登录、合法域名和流式传输方案。

### 验收标准

- 用户可以通过 HTTPS 链接或二维码在手机和微信内置浏览器访问。
- 账号、会话和消息在服务重启后仍然存在。
- 正式环境不依赖临时本地磁盘保存核心数据。
- 高风险安全流程、软删除和总管永久删除权限保持有效。
