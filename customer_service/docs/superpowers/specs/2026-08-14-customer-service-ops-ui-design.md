# 智能客服工作台前端改造设计

日期：2026-08-14

## 目标

将现有单页聊天界面改造成更稳定、清晰、适合长时间使用的客服工作台。页面仍然服务同一个核心任务：选择或新建会话，输入问题，查看智能客服回复，必要时转人工。

## 修改范围

只修改 `static/index.html`。

保留现有后端接口、会话恢复、发送消息、转人工和标题更新逻辑，不新增网络调用、不新增依赖、不引入遥测。

## 设计方向

采用“稳定工作台”风格，而不是营销页或强品牌展示页。

视觉系统：

- 主背景：`#eef2f7`，降低长时间阅读疲劳。
- 侧栏：`#17212f`，建立坐席工具感。
- 主操作蓝：`#2f6fed`，用于发送按钮和用户消息。
- 状态强调色：`#f2c14e`，用于当前会话的选中标识。
- 内容表面：`#ffffff` 和 `#f8fafc`，保持消息和输入区清楚分层。

排版使用现有系统中文字体栈，增加字号、字重和行高层级，不引入外部字体资源。

## 页面结构

保留两栏结构：

- 左侧会话栏：品牌标题、新建会话按钮、会话列表。
- 右侧聊天区：会话标题栏、消息列表、输入操作区。

新增或强化的界面层次：

- 顶部标题栏显示当前会话标题，并补充轻量状态文案，让页面更像“正在处理的会话”。
- 当前会话使用左侧琥珀色标识和深色高亮，避免只靠蓝色块判断状态。
- 消息区使用浅色网格/纸面感背景，消息气泡浮在其上，提升阅读边界。
- 输入区固定在底部，发送与转人工按钮保持稳定尺寸。

## 组件行为

会话列表：

- 继续使用 `loadSessions` 渲染。
- 保留标题截断，优化 hover、active、focus-visible 状态。

消息气泡：

- 用户消息右对齐，使用主操作蓝。
- 助手消息左对齐，使用白色表面、边框和轻阴影。
- loading 状态保留，但文案和样式更明确。

输入区：

- 保留 Enter 发送、Shift+Enter 换行。
- 发送按钮禁用时应有视觉反馈。
- 转人工按钮使用低饱和暖色，作为次级但明显的操作。

响应式：

- 桌面端保持左侧栏 + 主聊天区。
- 窄屏下侧栏改为顶部横向区域，会话列表横向滚动，聊天区占满剩余空间。
- 按钮和输入框不因文案长度造成布局跳动。

## 数据流

不改变数据流：

1. 初始化时根据 URL hash 恢复会话；没有 hash 则新建会话。
2. 会话列表来自 `GET /api/sessions`。
3. 会话详情来自 `GET /api/sessions/{id}`。
4. 用户发送消息后调用 `POST /api/chat/{id}`。
5. 转人工仍通过现有聊天接口提交转人工意图。

## 错误处理

保留现有 try/catch 行为。界面层面将失败消息改成清楚、可读的中文提示，不暴露内部错误，不输出凭据或环境变量。

## 测试与检查

最快相关检查：

- 启动本地服务后打开首页，确认页面能加载。
- 新建会话、发送消息、转人工按钮仍能触发原有流程。
- 检查桌面宽度和窄屏宽度下没有明显文字重叠或按钮挤压。

如果环境不具备模型/API 密钥，则只验证页面加载和前端交互事件绑定，不验证真实 AI 回复质量。
