# 自适应安全流式回复设计

## 目标

让「有话说」的普通回复更及时，同时保留对输入和输出消息的安全检查。低风险内容采用受约束的流式回复；高风险或不确定内容采用完整审核后再回复，避免普通问题被不必要的多次模型审核拖慢。

## 核心原则

- 安全等级决定回复路径，而不是所有消息使用同一条慢路径。
- 低风险模式通过严格提示词、短输出限制和滚动规则扫描控制风险。
- 高风险或审核不确定时不发送未审核的具体行动建议。
- 只有完整生成且成功结束的助手回复才写入消息数据库。
- 断线、取消或安全阻断时不保存半截助手回复。

## 风险分级

### 快速路径

满足以下条件时进入快速流式路径：

- 输入规则检查没有命中明确的自伤、伤人、暴力、违法、诈骗或危险操作风险。
- 输入长度和模式合法。
- 当前模式为 `companion` 或 `problem_solving`，且不包含需要专业判断的明显高风险主题。

快速路径不调用额外的输出审核模型，但必须执行提示词约束和输出滚动规则扫描。

### 保守路径

以下情况进入保守路径：

- 输入规则命中高风险词组或危险行动语义。
- 输入涉及医疗、法律、投资、药物、暴力或无法确认的严重危机。
- 安全判断结果不确定、解析失败或检查服务超时。
- 用户选择 `urgent` 模式。

保守路径完整生成回答，完成输入/输出安全审核后一次性返回 SSE 的单个安全回复事件，不发送未审核草稿。

## 输出约束

`problem_solving` 模式使用独立的短回答提示词：

- 最多 5 个段落。
- 最多 2 个方案。
- 只问 1 个最关键的澄清问题。
- 必须给出今天可以完成的第一步。
- 总长度限制为 400 tokens。
- 不重复长篇情绪安慰，不调用工具，不编造学校或机构联系方式。

普通 `companion` 模式也限制合理长度，但保留更自然的陪伴语气。

## 流式接口

新增：`POST /api/chat/{session_id}/stream`。

响应类型为 `text/event-stream`，事件格式固定为 JSON：

```text
event: start
data: {"session_id":"...","path":"fast"}

event: delta
data: {"text":"..."}

event: done
data: {"content_length":123}
```

错误和保守路径使用：

```text
event: error
data: {"message":"..."}
```

保守路径审核通过后可以发送一个 `delta` 事件和一个 `done` 事件；审核未通过时只发送安全兜底内容。所有事件中的文本都必须经过 JSON 编码，不能直接拼接用户输入。

现有 `POST /api/chat/{session_id}` 保留为非流式兼容接口，继续返回完整 `ChatResponse`。前端默认改用 `/stream`，便于旧客户端继续工作。

## 后端数据流

1. 验证用户身份和会话归属。
2. 写入用户消息。
3. 执行快速输入安全检查。
4. 根据风险等级选择快速或保守路径。
5. 快速路径使用 Agent 的异步流式接口读取模型增量文本。
6. 每个增量片段经过滚动扫描；扫描窗口保留足够尾部字符，避免危险短语跨片段被拆开后漏检。
7. 保守路径完整生成并执行输出安全审核，不发送草稿。
8. 流正常结束且内容非空时保存最终助手消息。
9. 发送 `done`，前端刷新会话列表。

## 滚动输出检查

快速路径维护一个有限长度的扫描窗口，检查：

- 自伤、伤人、暴力或危险操作的可执行步骤。
- 违法、诈骗、规避监管和凭据窃取指导。
- 虚假声称已经联系真人或执行外部操作。

扫描命中时：

- 立即停止继续读取模型输出。
- 尝试结束 Agent 流。
- 不保存当前助手草稿。
- 发送固定安全兜底事件和 `done`。

由于快速路径已经发送过之前的安全片段，滚动扫描不是绝对的内容隔离；因此任何输入级别的不确定性都必须进入保守路径。高风险内容不得进入快速路径。

## 前端行为

- `send()` 使用 `fetch` 获取流并通过 `ReadableStreamDefaultReader` 读取 SSE。
- 收到 `start` 后创建空助手气泡。
- 收到 `delta` 时追加文本并保持滚动到底部。
- 收到 `done` 后刷新会话标题和列表。
- 收到 `error` 或网络断开时移除未完成气泡并显示明确重试提示。
- 浏览器不支持流式读取时回退到现有 `/api/chat/{session_id}`。
- 快捷入口“帮我想办法”继续发送 `mode = problem_solving`。

## 安全与隐私

- 不在日志中记录完整用户输入、模型草稿、密码或认证令牌。
- 被阻断的模型草稿不写入 `messages` 表。
- 数据库只保存用户消息和最终允许发送的助手回复。
- SSE 不提供会话之外的用户数据。

## 测试范围

- 普通低风险请求产生顺序正确的 `start`、`delta`、`done` 事件。
- 多个增量片段拼接后等于最终助手内容。
- `problem_solving` 模式使用 400 tokens 限制和结构化提示词。
- 高风险输入不产生未审核的 `delta`，只返回安全回复。
- 输出滚动扫描能识别跨片段危险短语并停止流。
- 流中断或浏览器断开时不保存半截助手消息。
- SSE 错误可被前端解析并清除加载状态。
- 现有非流式接口、会话隔离、账号认证和上下文恢复测试继续通过。
- 桌面与移动端流式文本不会导致布局跳动或横向溢出。

## 非目标

- 不把流式输出当作安全审核替代品。
- 不让高风险内容为了追求速度进入快速路径。
- 不增加外部审核平台、遥测或内容上传服务。
- 不自动联系辅导员、学校或任何真人。
